# 심층 탄환 계정 서버

Node.js 24 이상에서 저장소 루트의 `shooter.html`과 `account-server/server.mjs`를 같은 배포에 포함한다. SQLite 데이터베이스는 재시작 후에도 남는 디스크에 두고 백업한다. 공개 배포 시 HTTPS 프록시로 연결한다.

```sh
GAME_DB=/path/to/persistent/game.sqlite node account-server/server.mjs
```

기본 주소는 `127.0.0.1:8080/shooter.html`이다. `HOST`와 `PORT`로 조정할 수 있다. 우편 발송을 활성화하려면 호스팅 환경에서 별도로 만든 32자 이상의 무작위 관리자 키를 `GAME_ADMIN_KEY`에 넣는다. 키는 코드, 저장소 또는 공유 링크에 넣지 않는다. 운영 프록시에서 계정 생성 요청에 속도 제한을 적용한다.

- 플레이어는 서버에서 게임을 열고 **메뉴 → 계정**에서 현재 기기의 진행을 등록한다. 다른 기기에서 연동 코드를 입력해 서버 기록을 불러온다. 동기화는 계정 화면에서 수동으로 실행한다.
- 개발자는 서버의 `/shooter.html?admin=1`을 열고 **메뉴 → 우편함**에서 수신자의 계정 ID와 관리자 키를 입력한다. 같은 이름을 쓰는 사용자가 있어도 계정 ID로 대상을 구분한다.
- 연동 코드는 비밀번호처럼 보관한다. 분실 시 이메일 재설정 기능은 없다. 공개 Pages 주소에서는 메뉴, 공지, 기기 내 이름 저장을 사용할 수 있다.
- 기존 Pages 기록은 브라우저의 사이트별 저장소에 있다. 새 서버 주소에서는 해당 기록이 자동으로 나타나지 않으므로 실제 이전에는 기록 파일을 내보내고 가져온 뒤 등록한다.

## 3.0 순위와 제보

게임의 **메뉴 → 순위**에서 계정을 연동한 유저가 직접 참가할 수 있다. 공개 화면은 서버가 만든 별칭과 진행 수치만 보여준다. 순위는 일반 클리어, 별, 폐광 알파 클리어, 레벨 순으로 계산한다. 브라우저에서 동기화한 기록을 사용하는 비공식 비교다.

제보는 계정 메뉴에서 보낼 수 있으며, 개발자는 관리자 키로 각 계정의 최근 제보를 확인할 수 있다.

## 4.0 마지막 교신

저장소 루트의 Dockerfile로 Node 24 서버와 게임 화면을 함께 실행할 수 있다. Railway에서 저장소를 연결하고 볼륨을 /data에 연결한 뒤 공개 도메인을 생성한다. 포트는 호스팅이 지정하는 PORT를 사용한다. 계정 우편을 발송하려면 GAME_ADMIN_KEY를 별도로 설정한다.

새 주소의 /signal.html#coop 에서 두 사람이 방 코드로 참가한다. 방은 단일 서버 프로세스 메모리에 있으며 재시작하면 닫힌다. 전투 중 연결이 끊기면 같은 탭에서 30초 안에 돌아올 수 있다. 한 서버 인스턴스로 운영한다. 정적 Pages에서는 개조 작전과 폐광 탐사가 동작한다.
